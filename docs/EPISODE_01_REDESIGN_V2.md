## 1. Chapter 1 구성

Chapter 1은 하나의 큰 사건을 네 개의 Episode로 나누어 진행한다.

1. Episode 1 `중앙 정원의 흔적`
   - 약수의 의미와 약수 찾기
2. Episode 2 `연못의 잠긴 수문`
   - 공약수와 최대공약수
3. Episode 3 `반복되는 숲의 불빛`
   - 배수, 공배수와 최소공배수
4. Episode 4 `별빛 씨앗의 행방`
   - 약수와 배수 종합 추리 및 사건 해결

기존 Episode 1에서 한 번에 다루던 공배수, 최대공약수, 포포 발견과 최종 결말은 학습 순서에 맞춰 후속 Episode로 이동한다.

## 2. Episode 1 목표

Episode 1은 약수 단원 전체를 끝내는 짧은 퀴즈가 아니다. 플레이어가 중앙 정원의 물건과 흔적을 조사하면서 약수의 뜻과 약수를 빠짐없이 찾는 방법을 여러 게임 행동으로 반복한다.

완료 시 플레이어는 다음을 할 수 있어야 한다.

- 나머지 없이 나누어지는 수를 약수로 판단한다.
- 같은 수씩 묶기와 배열을 통해 약수를 찾는다.
- 곱셈 짝을 이용해 약수를 빠짐없이 찾는다.
- 1과 자기 자신을 약수에 포함한다.
- 약수가 아닌 수를 근거를 들어 제외한다.
- 찾은 약수를 사건 단서와 경로 추리에 적용한다.

## 3. 플레이 분량

- 권장 플레이 시간: 15~18분
- 필수 학습 활동: 14개
- 조건부 보강 활동: 최대 2개
- 핵심 단서: 6개
- 중간 자동 저장: 1회

학습 활동 14개는 객관식 문제 14문항을 뜻하지 않는다. 조사, 묶기, 배열, 장치 조작, 기록 복구와 증거 추리를 각각 하나의 학습 활동으로 본다.

## 4. 필수 학습 활동 14개

1. 떨어진 별조각을 맞는 홈에 끼우기
2. 별가루 12개를 같은 수씩 묶어 보기
3. 12개를 남김없이 놓을 수 있는 받침대 모두 찾기
4. `1×12`, `2×6`, `3×4` 곱셈 짝 복구
5. 12의 약수를 작은 수부터 순서대로 배열
6. 긁힌 별가루 18개를 가능한 직사각형 배열로 만들기
7. 뒤집혀 중복된 18의 곱셈 짝 정리
8. `1, 2, 3, □, 9, 18`에서 빠진 약수 찾기
9. 18의 약수가 아닌 후보 제거
10. 별꽃 씨앗 24개의 가능한 배열 실험
11. 24의 약수 목록 완성
12. 잘못된 정원사 기록 판별
13. 24칸 별돌에서 약수 조건과 방향 단서를 결합해 실제 발자국 경로 판별
14. 사건 카드를 시간 순서로 배열하고 중간 결론 선택

## 5. 조건부 활동

### 보강 활동

약수 판별에서 두 번 이상 연속으로 어려움을 보이면, 실제 별가루가 남는지 확인하는 짧은 재배치 활동을 제공한다.

### 도전 활동

필수 활동을 힌트 없이 빠르게 해결하면 30개의 별구슬을 이용한 전이 문제를 제공한다. 필수 진행에는 영향을 주지 않고 수집품만 지급한다.

## 6. Episode 1 사건 범위

Episode 1에서 확정하는 사실은 다음과 같다.

- 씨앗은 누군가가 받침대에서 들어 간 것이 아니다.
- 강한 바람에 오른쪽으로 미끄러져 떨어졌다.
- 작은 발자국은 씨앗이 떨어진 지점부터 시작한다.
- 발자국은 연못 방향으로 이어진다.
- 발자국의 주인이 씨앗을 훔쳤는지는 아직 알 수 없다.

Episode 1은 연못 입구에서 젖은 은빛 털과 잠긴 수문 문양을 발견하며 끝난다. 씨앗과 포포 발견, 별빛 꽃 개화와 사건 전체 해결은 Episode 4로 이동한다.

## 7. 스토리와 학습의 결합 원칙

- 별도 문제 화면을 연속으로 제시하지 않는다.
- 수학 활동 최대 두 개 뒤에는 단서, 아이템, 장면 변화 또는 대사를 제공한다.
- 문제의 숫자는 임의로 표시하지 않고 이전 조사에서 발견한다.
- 틀린 선택은 벌점 대신 남는 별가루나 불완전한 배열로 보여준다.
- 이전 단서 없이는 후속 경로나 결론을 확정할 수 없게 한다.
- 같은 문제 형식을 세 번 이상 연속으로 사용하지 않는다.

## 8. 설치형 앱 화면 기준

Rumi의 주 사용 환경은 모바일 브라우저 탭이 아니라 홈 화면에 설치한 Web App 또는 향후 Android 앱으로 정한다.

### 8.1 기본 표시 기준

- Web App manifest: `display: standalone`
- 기본 방향: 세로 `portrait-primary`
- 게임 배경은 앱 화면 전체를 사용한다.
- 상단 HUD, 단서 수첩, 상태 메시지와 인벤토리만 시스템 안전영역 안에 둔다.
- 브라우저 주소창과 하단 도구 모음이 있는 일반 탭 화면은 보조 테스트 환경으로 취급한다.

### 8.2 안전영역

다음 영역에 진행 버튼과 중요한 단서를 배치하지 않는다.

- Android 상태바
- 카메라 홀과 노치
- 하단 제스처 내비게이션 영역
- 둥근 화면 모서리
- iOS 설치형 Web App의 상태바 영역

고정된 상단·하단 픽셀값만 사용하지 않고 `MediaQuery`의 실제 안전영역과 현재 앱 화면 크기를 반영한다.

### 8.3 기준 화면

- 최소 대응: 360×640 논리 픽셀
- 일반 스마트폰: 360~430 폭
- Galaxy 태블릿 세로 화면: 앱이 제공하는 전체 세로 viewport
- 시스템 안전영역이 상단 28, 하단 24인 최소 화면에서도 HUD와 인벤토리가 겹치지 않아야 한다.

### 8.4 UI 우선순위

화면 높이가 부족할 때는 다음 순서로 공간을 줄인다.

1. 목표 설명을 두 줄에서 한 줄로 축약
2. 상태 메시지를 한 줄로 축약
3. 장식 여백 축소
4. 배경 장식 밀도 축소

다음 요소는 줄이거나 가리지 않는다.

- 주요 조작 대상
- 뒤로 가기
- 단서 수첩
- 인벤토리
- 현재 진행에 필요한 숫자와 배열

## 9. 현재 적용된 기반 변경

- Episode 1의 게임 배경을 전체 앱 viewport에 표시
- 상단 HUD와 인벤토리를 실제 시스템 안전영역에 맞춰 배치
- 고정 좌우 좌표의 상단 버튼을 반응형 Row로 변경
- 작은 높이에서는 목표와 상태 문구를 한 줄로 축약
- Web App viewport에 `viewport-fit=cover` 적용
- manifest 이름, 설명, 테마색, scope와 세로 방향 정리
- 설치형 앱 안전영역 자동 테스트 추가

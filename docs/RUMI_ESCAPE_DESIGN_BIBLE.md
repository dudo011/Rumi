## 1. 문서 목적

이 문서는 Rumi의 방탈출 에피소드를 설계하고 구현할 때 따라야 하는 공통 기준을 확정한다.

Episode 1을 포함한 이후 에피소드는 이 문서의 장면 구조, 상호작용, 아이템, 퍼즐, 힌트, 교육 적용, 연출, 기술 분리와 검증 기준을 따라야 한다.

이 문서는 아이디어 모음이 아니라 제작 기준이다. 개별 에피소드에서 다른 방식을 사용하려면 상세 설계 단계에서 이유와 검증 방법을 먼저 명시한다.

---

## 2. 최종 게임 정의

Rumi는 다음 형식의 게임이다.

> 초등학교 5학년 아이가 2D 장면을 관찰하고, 수상한 물건을 직접 만지고, 다른 장소에서 얻은 단서와 아이템을 연결하여 약 10분 안에 하나의 사건을 해결하는 캐릭터 중심 방탈출 게임.

학습 문제를 통과해야 진행되는 앱이 아니다. 장면과 장치의 규칙을 이해하고 사건을 해결하는 과정에서 수학을 사용한다.

---

## 3. 변경하지 않는 핵심 원칙

1. 게임의 중심은 장면 탐색과 사건 해결이다.
2. 플레이어는 안내된 순서를 따라 누르는 사람이 아니라 스스로 관찰하고 추론하는 별지기다.
3. 첫 30초 안에 설명 없이 이해할 수 있는 작은 성공을 제공한다.
4. 모든 핵심 행동은 장면, 물건, 빛, 소리 또는 이야기의 변화로 이어진다.
5. 오답은 벌점이 아니라 세계의 규칙을 이해하게 하는 피드백이다.
6. 수학은 객관식 문제창이 아니라 분류, 배치, 반복, 개수, 규칙과 추론에 사용한다.
7. 경쟁, 순위, 체력 감소, 시간 압박과 실패 화면을 핵심 동기로 사용하지 않는다.
8. 사건 해결 후에는 정원과 루미에게 눈에 보이는 변화가 남는다.
9. 한 에피소드는 완결되지만 다음 에피소드로 이어지는 질문 하나를 남긴다.
10. 완전한 3D, 정밀 물리, 반사신경 중심 조작은 사용하지 않는다.

## 4. 목표 감정 흐름

한 세션에서 플레이어가 느껴야 하는 감정은 다음 순서를 따른다.

```text
무슨 일이 있었지?
→ 저 물건이 수상해
→ 내가 찾아냈어
→ 이건 어디에 쓰지?
→ 아까 본 장면과 연결된다
→ 내가 움직이자 세계가 변했다
→ 이제 사건을 설명할 수 있어
→ 다음에는 무슨 일이 생길까?
```

다음 감정은 만들지 않는다.

- 무엇을 눌러야 할지 전혀 알 수 없음
- 작은 물건을 찾지 못해 막힘
- 수학 문제가 갑자기 나타나 흐름이 끊김
- 정답을 맞혔지만 장면은 그대로임
- 틀렸다는 이유로 손해를 봄
- 힌트를 봐도 다음 행동을 알 수 없음

## 5. 10분 세션 구조

기본 에피소드 목표 시간은 8~12분이며 설계 기준은 약 10분이다.

| 구간 | 목표 시간 | 역할 |
|---|---:|---|
| 사건 제시와 첫 성공 | 0~1분 | 목적 이해, 즉시 조작 성공 |
| 자유 관찰과 첫 단서 | 1~3분 | 주요 장면 파악, 수상한 물건 발견 |
| 아이템·단서 연결 | 3~6분 | 장면 왕복, 확대 조사, 퍼즐 해결 |
| 큰 장치 변화 | 6~8분 | 연쇄 작동, 숨겨진 공간 공개 |
| 최종 추리와 결말 | 8~10분 | 증거 연결, 사건 해결, 다음 질문 |

시간을 맞추기 위해 대사를 줄이거나 정답을 쉽게 만드는 것이 아니라, 불필요한 장면과 중복 퍼즐을 제거한다.

## 6. 기본 게임 루프

모든 에피소드의 핵심 루프는 다음과 같다.

```text
장면 관찰
→ 조사 대상 선택
→ 반응 또는 확대 조사
→ 단서·아이템·규칙 발견
→ 다른 장면과 연결
→ 장치 조작 또는 퍼즐 해결
→ 장면 상태 변화
→ 새 탐색 범위 개방
```

이 루프는 한 에피소드에서 최소 3회 반복한다.

각 반복은 이전 반복보다 의미가 커져야 한다.

1. 첫 반복: 작은 물건 또는 단서 발견
2. 두 번째 반복: 다른 장면과 연결하여 장치 작동
3. 세 번째 반복: 사건의 핵심 공간 또는 최종 증거 공개

## 7. 에피소드 전체 구조

### 7.1 장면 수

- 주요 장면: 4~6개
- 확대 조사 장면: 3~5개
- 최종 추리 또는 결말 화면: 1개
- 동시에 기억해야 하는 활성 목표: 최대 2개

장면을 늘려 플레이 시간을 확보하지 않는다. 같은 장면이 진행에 따라 다른 의미와 기능을 갖게 한다.

### 7.2 권장 공간 구조

```text
중심 장면
├── 장면 A
├── 장면 B
└── 장면 C

각 장면
└── 필요한 경우 확대 조사 1~2개
```

중심 장면은 전체 사건의 상태가 가장 크게 변하는 장소다. 플레이어가 다른 장면을 조사한 뒤 돌아왔을 때 진행 결과를 한눈에 확인할 수 있어야 한다.

### 7.3 개방 순서

모든 장면과 오브젝트를 처음부터 활성화하지 않는다.

- 처음부터 보이지만 아직 의미를 모르는 물건
- 특정 단서 후 반응이 달라지는 물건
- 장치 작동 후 새로 나타나는 통로
- 해결 후 기능을 잃거나 새로운 기능을 얻는 물건

이 네 가지 상태 변화를 조합해 탐색 범위를 단계적으로 연다.

## 8. 장면 설계 규칙

### 8.1 장면의 역할

각 주요 장면은 다음 중 하나의 주 역할을 가진다.

- 사건의 변화가 보이는 중심 장면
- 아이템을 발견하는 탐색 장면
- 규칙을 관찰하는 단서 장면
- 물건을 배치하거나 조작하는 퍼즐 장면
- 숨겨진 사실을 공개하는 이야기 장면

한 장면에 모든 기능을 몰아넣지 않는다.

### 8.2 중심 오브젝트

각 주요 장면에는 시선이 먼저 가는 중심 오브젝트를 하나 둔다.

중심 오브젝트는 다음 조건을 만족한다.

- 화면 크기와 위치로 구분된다.
- 배경과 형태 또는 밝기 차이가 있다.
- 사건 또는 현재 목표와 관계가 있다.
- 진행 전과 후의 변화가 명확하다.

### 8.3 장면 상태

모든 주요 장면은 최소 다음 상태를 가진다.

1. 최초 방문 상태
2. 단서 또는 아이템 획득 후 상태
3. 주요 퍼즐 해결 후 상태

중심 장면은 가능하면 다음 상태까지 가진다.

4. 사건 해결 후 최종 상태

상태 변화는 텍스트만 바꾸지 않는다. 물건 위치, 조명, 색, 열림·닫힘, 움직임, 소리 중 최소 하나가 달라져야 한다.

### 8.4 재방문 이유

이전 장면으로 돌아가게 할 때는 다음 중 하나가 반드시 있어야 한다.

- 새 아이템을 사용할 수 있음
- 이전에는 읽지 못한 단서의 의미가 바뀜
- 장치가 작동하여 장면이 변함
- 새로운 통로나 확대 조사 지점이 열림
- 루미의 반응 또는 이야기 정보가 달라짐

단순히 이동 거리를 늘리기 위한 왕복은 금지한다.

### 8.5 장면 이동

- 이동 방향은 실제 공간 관계와 일치시킨다.
- 동일한 출입구는 항상 같은 장면으로 연결한다.
- 뒤로 가기와 장면 이동을 혼동시키지 않는다.
- 확대 조사 화면의 뒤로 가기는 반드시 원래 장면으로 돌아간다.
- 이동 후 현재 목표와 선택된 아이템 상태를 유지한다.

---

## 9. 조사 오브젝트 규칙

### 9.1 오브젝트 분류

모든 장면 오브젝트는 다음 중 하나로 분류한다.

| 분류 | 역할 |
|---|---|
| 진행 오브젝트 | 퍼즐, 아이템, 단서 또는 새 장면을 연다 |
| 연결 오브젝트 | 다른 장면의 단서나 아이템과 관계가 있다 |
| 보조 단서 | 사건 이해와 추리를 돕지만 직접 진행을 열지 않는다 |
| 분위기 오브젝트 | 세계관과 상황을 설명한다 |
| 해결 오브젝트 | 이미 해결되었음을 보여주고 불필요한 재조사를 줄인다 |

역할이 정의되지 않은 오브젝트를 조사 가능하게 만들지 않는다.

### 9.2 반응 의무

조사 가능해 보이는 물건은 반드시 반응한다.

가능한 반응은 다음과 같다.

- 짧은 움직임
- 확대 조사
- 상황 설명
- 필요한 아이템 형태 안내
- 현재는 사용할 수 없다는 이유
- 이전 조사와 달라진 반응
- 루미의 짧은 관찰

`아무 일도 일어나지 않았다`만 반복하지 않는다.

### 9.3 터치 영역

- 주요 오브젝트의 최소 터치 영역은 48×48 논리 픽셀 이상으로 한다.
- 보이는 그림보다 터치 영역을 넓게 설정한다.
- 서로 가까운 오브젝트의 터치 영역은 겹치지 않게 한다.
- 손가락이 가려도 선택 결과를 빛, 테두리 또는 움직임으로 확인할 수 있게 한다.

### 9.4 조사 완료 표시

이미 확인한 오브젝트를 무조건 비활성화하지 않는다.

- 다시 볼 필요가 없는 물건: 시각적으로 해결 상태 표시
- 후반에 의미가 바뀌는 물건: 계속 조사 가능
- 아이템 획득 장소: 빈 자리 또는 열린 상태 표시
- 핵심 단서: 단서 수첩에서 다시 확인 가능

## 10. 상호작용 문법

플레이어는 다음 조작만으로 모든 에피소드를 이해할 수 있어야 한다.

### 10.1 탭

용도:

- 물건 조사
- 장면 이동
- 아이템 선택과 해제
- 버튼 또는 장치 누르기
- 대화 진행

규칙:

- 한 번 누르면 한 가지 명확한 반응이 발생한다.
- 반복 탭이 필요한 장치는 탭할 때마다 변화가 보여야 한다.
- 빠른 연속 탭을 요구하지 않는다.

### 10.2 드래그

용도:

- 아이템을 사용처로 이동
- 조각을 분류하거나 배치
- 손잡이 또는 덮개 이동

규칙:

- 한 화면의 동시 조각은 가능한 6개 이하로 제한한다.
- 목표 지점은 조각을 잡기 전에도 알아볼 수 있어야 한다.
- 성공 범위 안에 놓으면 자동 스냅한다.
- 실패하면 원위치로 자연스럽게 돌아간다.
- 정밀한 손가락 위치를 요구하지 않는다.

### 10.3 제한 회전

용도:

- 문양 맞추기
- 방향 조정
- 간단한 다이얼

규칙:

- 자유 회전이 아니라 정해진 각도 단위로 이동한다.
- 한 번의 조작 결과가 즉시 보인다.
- 미세한 각도 맞추기를 요구하지 않는다.

### 10.4 확대 조사

- 전체 장면에서 한 물건에 집중할 때 사용한다.
- 확대 화면에는 실제 조사 대상만 남긴다.
- 확대 화면 안에 다시 복잡한 다단계 확대를 중첩하지 않는다.
- 원래 장면과의 관계를 잃지 않게 제목 또는 배경 특징을 유지한다.

## 11. 인벤토리 설계

### 11.1 기본 구조

인벤토리는 Flutter Overlay로 구현한다.

- 획득한 아이템을 항상 확인할 수 있다.
- 아이템을 눌러 선택하거나 다시 눌러 해제한다.
- 선택 상태는 테두리, 빛 또는 크기 변화로 명확히 표시한다.
- 장면 이동 후에도 선택 상태를 유지한다.
- 모달 화면이 열리면 배경 장면 입력을 차단한다.

### 11.2 아이템 수

- 한 에피소드 총 아이템: 4~7개
- 동시에 보유하는 미사용 아이템: 가능한 4개 이하
- 장식용 또는 용도가 없는 아이템은 만들지 않는다.

### 11.3 사용처 추론

아이템은 이름을 읽지 않아도 형태와 상황으로 사용처를 추측할 수 있어야 한다.

좋은 예:

- 별 모양 열쇠와 별 모양 열쇠구멍
- 비어 있는 원형 홈과 둥근 조각
- 끊어진 줄과 연결용 고리

나쁜 예:

- 의미 없는 물건을 임의의 장소에 사용
- 설명을 읽어야만 알 수 있는 조합
- 여러 장소에 무작위로 대입해야 하는 아이템

### 11.4 올바른 사용

올바른 아이템을 사용하면 다음 순서로 반응한다.

```text
즉시 접촉 반응
→ 아이템 또는 장치 이동
→ 짧은 연쇄 작동
→ 새 단서·공간·상태 공개
```

아이템 사용 결과를 문구로만 알리지 않는다.

### 11.5 잘못된 사용

잘못된 아이템은 소모하지 않는다.

피드백은 다음 정보를 하나 이상 제공한다.

- 형태가 맞지 않음
- 크기가 맞지 않음
- 현재 상태에서는 사용할 수 없음
- 다른 도구가 먼저 필요함
- 물건의 실제 성질

예:

> 꽃잎은 부드러워서 단단한 자물쇠를 돌릴 수 없어요.

`틀렸어요`만 표시하지 않는다.

### 11.6 아이템 소모

- 한 번 사용 후 역할이 끝나면 인벤토리에서 제거한다.
- 이후 단서로 다시 확인해야 하면 사용 완료 상태로 남긴다.
- 자동 사용하지 않는다. 플레이어가 직접 선택하고 사용한다.

---

## 12. 단서와 단서 수첩

### 12.1 단서의 역할

단서는 다음 중 하나의 질문에 답해야 한다.

- 누가 이곳을 지나갔는가
- 어느 방향으로 이동했는가
- 어떤 물건이 사용되었는가
- 어떤 순서 또는 반복 규칙이 있는가
- 이전 장면의 물건을 어떻게 해석해야 하는가

### 12.2 단서 수첩

단서 수첩은 Flutter Overlay로 구현한다.

각 단서는 다음 정보를 가진다.

- 짧은 이름
- 발견한 장면
- 관찰한 사실
- 아직 확정되지 않은 의미
- 다른 단서와 연결된 경우 연결 표시

수첩이 정답을 대신 설명하지 않는다. 플레이어가 발견한 사실을 기억하도록 돕는다.

### 12.3 단서 연결

에피소드에는 최소 다음 연결이 있어야 한다.

- 한 장면에서 본 정보가 다른 장면의 장치를 푸는 연결 2회 이상
- 초반에 본 물건의 의미가 후반에 달라지는 재해석 1회 이상
- 최종 사건 설명에 사용되는 핵심 증거 3개

단서 개수만 채우면 마지막 단계가 열리는 구조는 사용하지 않는다.

## 13. 퍼즐 설계 기준

### 13.1 퍼즐의 필수 조건

모든 퍼즐은 다음 네 조건을 통과해야 한다.

1. 왜 이 장소에 이 장치가 있는지 이야기상 설명된다.
2. 필요한 규칙 또는 단서를 게임 안에서 관찰할 수 있다.
3. 무작위 시행착오 없이 합리적으로 추론할 수 있다.
4. 해결 결과가 새 정보, 아이템, 공간 또는 시각 변화로 이어진다.

한 조건이라도 충족하지 못하면 퍼즐을 수정하거나 제거한다.

### 13.2 퍼즐 수

- 핵심 퍼즐: 4~6개
- 짧은 예비 조작: 1~2개
- 최종 추리: 1개
- 한 장면 안의 연속 퍼즐: 최대 2개

### 13.3 난이도 곡선

```text
직관적 조작
→ 한 장면 안의 관찰
→ 다른 장면과 연결
→ 아이템과 규칙 결합
→ 여러 증거를 연결한 최종 추리
```

첫 퍼즐보다 마지막 퍼즐이 단순 계산만 더 어려워지는 방식은 사용하지 않는다. 기억해야 할 관계와 의미가 점차 깊어져야 한다.

### 13.4 채택 퍼즐 유형

#### A. 바로 사용 가능

- 탭 순서
- 개수 세기와 묶기
- 형태 맞추기
- 조각 드래그와 스냅
- 간단한 분류
- 반복 패턴 관찰
- 제한 각도 회전
- 다른 장면의 배열 비교
- 흔적 복원
- 아이템 사용 순서
- 두 규칙이 만나는 위치 찾기

#### B. 제한적으로 사용

다음 유형은 에피소드의 핵심 재미에 반드시 필요한 경우에만 별도 검증한다.

- 확대와 이동이 함께 필요한 큰 퍼즐판
- 6개를 초과하는 복수 조각 드래그
- 여러 장면에 영향을 주는 긴 연쇄 장치
- 짧은 시간 제한
- 반복되는 복합 카메라 연출

### 13.5 금지 퍼즐 유형

- 자유로운 3D 물체 회전
- 정밀 물리 시뮬레이션
- 반사신경 중심 퍼즐
- 외부 메모가 필요한 복잡한 암호
- 미세한 색 차이 구분
- 작은 물건을 픽셀 단위로 찾기
- 긴 숫자 또는 계산식 직접 입력
- 이야기와 무관한 숫자 자물쇠
- 무작위 조합을 전부 시도해야 하는 장치

## 14. 수학 적용 규칙

### 14.1 기본 원칙

수학은 다음 역할 중 하나를 가져야 한다.

- 어떤 물건을 선택할지 판단
- 물건을 몇 개씩 묶을지 결정
- 장치의 배열과 구조 해석
- 흔적의 반복 규칙으로 위치 발견
- 여러 가능성 중 맞지 않는 경우 제거

수학을 별도 문제창으로 분리하지 않는다.

### 14.2 약수와 배수 적용 예시

- 별가루 12개를 같은 수씩 나누어 홈 활성화
- 2칸과 3칸 반복 흔적이 함께 나타나는 위치 찾기
- 장치의 전체 개수와 맞는 묶음 선택
- 특정 수의 약수에 해당하는 꽃잎 또는 문양 배치
- 여러 발자국 주기의 공통 위치를 통해 이동 방향 추론

### 14.3 교육 적용 5단계

```text
장면에서 물리적 대상 관찰
→ 개수 또는 반복 규칙 발견
→ 직접 분류·배치·선택
→ 장치가 작동하며 결과 확인
→ 사건 단서로 의미 연결
```

### 14.4 금지 방식

- `12의 약수를 고르세요`와 같은 객관식 팝업
- 문제를 맞히면 unrelated 아이템 지급
- 틀리면 경험치, 체력 또는 기회 감소
- 이야기상 근거 없는 계산 문제
- 풀이 과정 없이 답만 누르는 구조
- 수학 퍼즐과 사건 추리가 서로 영향을 주지 않는 구조

### 14.5 학습 난이도

- 새로운 개념을 시험하지 않고 이미 배운 개념을 게임 규칙으로 사용한다.
- 한 퍼즐에는 핵심 수학 개념 하나만 사용한다.
- 계산보다 관찰과 조작을 우선한다.
- 같은 개념을 다른 장면에서 반복하되 표현은 바꾼다.
- 정답 후에는 수학 설명보다 장치와 사건의 결과를 먼저 보여준다.

## 15. 힌트 시스템

### 15.1 기본 원칙

- 힌트 버튼은 항상 접근 가능하다.
- 힌트 사용에 점수나 보상 불이익을 주지 않는다.
- 힌트는 정답을 먼저 말하지 않고 다음 관찰을 돕는다.
- 플레이어가 요청하지 않은 정답을 자동으로 표시하지 않는다.

### 15.2 3단계 힌트

모든 핵심 퍼즐은 다음 세 단계 힌트를 가진다.

| 단계 | 역할 | 예시 |
|---|---|---|
| 1단계: 목표 | 무엇을 알아내야 하는지 알려준다 | 두 흔적이 함께 나타나는 곳을 찾아보세요. |
| 2단계: 위치 | 어디를 다시 봐야 하는지 알려준다 | 발자국과 별가루가 이어진 길을 비교해 보세요. |
| 3단계: 행동 | 구체적으로 무엇을 해야 하는지 알려준다 | 2칸과 3칸 표시가 동시에 있는 여섯 번째 칸을 눌러보세요. |

### 15.3 힌트 표시

- 첫 힌트 사용 전에는 텍스트만 제공한다.
- 두 번째 힌트부터 필요한 경우 관련 장면 이름 또는 단서 수첩 항목을 강조한다.
- 세 번째 힌트에서도 자동 해결하지 않는다.
- 접근성상 필요한 경우 목표 오브젝트를 짧게 빛낼 수 있다.

### 15.4 막힘 감지

다음 상황에서는 힌트 버튼에 부드러운 시각 강조만 제공할 수 있다.

- 같은 오답 행동을 3회 반복
- 같은 장면만 오래 조사
- 핵심 아이템을 보유하고도 사용하지 못함

힌트를 강제로 열거나 플레이를 중단하지 않는다.

## 16. 오답과 실패 처리

### 16.1 오답 반응 순서

```text
행동 즉시 반응
→ 왜 맞지 않는지 짧은 설명
→ 필요한 조건을 간접적으로 제시
→ 즉시 다시 시도 가능
```

### 16.2 금지되는 실패 처리

- 체력 감소
- 경험치 차감
- 획득 아이템 상실
- 장면 진행 초기화
- 긴 실패 애니메이션
- 조롱하거나 실망하는 캐릭터 반응
- `틀렸습니다`만 표시

### 16.3 안전한 긴장감

긴장감은 손해가 아니라 다음 요소로 만든다.

- 아직 열리지 않은 공간
- 의미를 모르는 단서
- 이전 장면의 눈에 띄는 변화
- 장치가 곧 움직일 것 같은 시각 반응
- 사건에 대한 제한된 정보

---

## 17. 최종 추리

### 17.1 역할

최종 추리는 단서를 모두 모았는지 확인하는 화면이 아니다. 플레이어가 발견한 증거를 사건 설명으로 연결하는 마지막 퍼즐이다.

### 17.2 구성

- 핵심 증거 3개를 사용한다.
- 가능한 설명은 2~3개로 제한한다.
- 틀린 설명도 일부 증거와는 맞아 보이게 만든다.
- 정답은 모든 핵심 증거를 가장 자연스럽게 설명한다.

### 17.3 오답 처리

오답을 선택하면 어떤 증거가 설명되지 않는지 알려준다.

예:

> 이 설명으로는 별받침대 옆으로 이어진 긁힌 방향을 설명하기 어려워요.

정답을 바로 공개하지 않는다.

### 17.4 결말

정답 후에는 다음 순서를 따른다.

```text
증거 연결 확인
→ 사건의 실제 행동 공개
→ 오해받은 캐릭터의 감정 설명
→ 중심 장면의 큰 변화
→ 꽃루미의 짧은 반응
→ 다음 사건의 질문 하나
```

---

## 18. 이야기와 캐릭터 규칙

### 18.1 사건 구조

Rumi의 사건은 악당을 잡는 구조보다 오해를 풀고 사정을 이해하는 구조를 우선한다.

좋은 결말:

- 누군가 물건을 숨긴 이유가 보호 또는 도움과 관계됨
- 이상한 흔적이 장난이 아니라 상황 대응의 결과였음
- 플레이어가 증거를 통해 캐릭터를 다시 이해함

### 18.2 꽃루미의 역할

꽃루미는 정답을 알려주는 안내자가 아니다.

역할:

- 사건의 감정적 중요성을 짧게 전달
- 플레이어의 관찰과 시도를 인정
- 공포나 실패감을 완화
- 결말에서 관계 변화를 보여줌

금지:

- 다음에 누를 물건을 계속 지시
- 플레이어보다 먼저 결론을 말함
- 오답에 실망하거나 꾸짖음
- 긴 설명으로 장면 탐색을 중단

### 18.3 대사 길이

- 일반 반응: 1문장
- 핵심 단서: 최대 2문장
- 사건 전환: 최대 3문장
- 결말: 짧은 대화 3~5회

긴 설정 설명은 장면과 물건에 나누어 배치한다.

---

## 19. 시각 설계 규칙

### 19.1 화면 우선순위

한 화면의 시각 우선순위는 다음 순서다.

1. 현재 장면과 중심 오브젝트
2. 조사 가능해 보이는 주요 물건
3. 장면 이동 지점
4. 인벤토리와 힌트
5. 보조 정보

UI가 장면보다 더 강하게 보이지 않게 한다.

### 19.2 조사 가능성 표현

모든 조사 대상을 같은 방식으로 반짝이게 하지 않는다.

- 중심 오브젝트: 형태, 위치, 조명으로 자연스럽게 강조
- 현재 목표와 직접 관련된 물건: 짧고 약한 빛 또는 움직임
- 이미 해결한 물건: 안정된 색과 열린 상태
- 힌트 요청 후: 필요한 대상만 일시적으로 강조

### 19.3 상태 변화

정답 직후에는 다음 중 최소 3개를 결합한다.

- 물체 이동 또는 회전
- 빛의 방향과 밝기 변화
- 덮개, 문, 서랍 열림
- 입자 또는 별빛 효과
- 효과음
- 카메라의 짧은 집중
- 새 공간 또는 아이템 공개

### 19.4 카메라

- 고정 장면을 기본으로 한다.
- 정답 연출에서만 짧은 이동 또는 확대를 사용한다.
- 플레이 중 자유 카메라 조작을 요구하지 않는다.
- 카메라가 움직이는 동안 입력을 잠근다.
- 연출 후 플레이어가 조작할 위치를 화면 안에 남긴다.

### 19.5 가독성

- 중요한 물건을 화면 가장자리와 SafeArea에 붙이지 않는다.
- 텍스트는 배경과 충분한 대비를 갖는다.
- 색만으로 상태를 구분하지 않는다.
- 미세한 색조 차이를 퍼즐 정답으로 사용하지 않는다.

## 20. 소리와 음악 규칙

### 20.1 효과음 역할

효과음은 다음 순간을 구분한다.

- 물건 조사
- 아이템 획득
- 올바른 아이템 결합
- 잘못된 사용
- 조각 스냅
- 장치 단계별 작동
- 비밀 공간 공개
- 사건 해결

### 20.2 정답 연출

큰 퍼즐 해결 시 한 번의 성공음만 재생하지 않는다.

```text
접촉음
→ 장치 이동음
→ 잠금 해제음
→ 공간 공개음
```

장면의 움직임과 소리를 같은 순서로 맞춘다.

### 20.3 배경음

- 탐색을 방해하지 않는 낮은 강도로 사용한다.
- 장면마다 완전히 다른 음악보다 사건 진행에 따라 층을 추가한다.
- 최종 추리에서는 긴장감을 약간 높이고 결말에서는 안정시킨다.
- 앱 백그라운드 전환 시 일시정지하고 복귀 시 재개한다.

### 20.4 무음 대응

소리를 듣지 않아도 모든 퍼즐을 해결할 수 있어야 한다. 소리는 정답 단서가 아니라 피드백과 분위기에 사용한다.

## 21. UI와 Overlay 규칙

### 21.1 Flutter Overlay 사용 대상

- 인벤토리
- 힌트
- 단서 수첩
- 짧은 대화
- 현재 목표
- 일시정지와 설정
- 최종 추리 선택지

### 21.2 Flame 사용 대상

- 장면 배경
- 조사 오브젝트
- 장면 이동 지점
- 드래그와 장치 조작
- 오브젝트 애니메이션
- 카메라와 시각 효과

### 21.3 입력 우선순위

1. 모달 Overlay가 열려 있으면 Flame 입력 차단
2. 인벤토리 아이템 선택은 장면 탭과 분리
3. 장치 연출 중에는 장면 이동과 반복 입력 차단
4. Overlay를 닫으면 기존 장면 상태로 즉시 복귀

### 21.4 화면 배치

- 뒤로 가기: 좌측 상단 SafeArea
- 힌트와 수첩: 우측 상단 SafeArea
- 인벤토리: 하단 또는 한쪽 가장자리의 고정 영역
- 현재 목표: 장면을 가리지 않는 짧은 한 줄
- 개발용 버튼: 정식 에피소드에는 포함하지 않는다.

## 22. 진행 상태와 저장

### 22.1 상태 구분

에피소드 상태는 다음 범주로 분리한다.

- 현재 장면
- 장면별 상태
- 오브젝트별 조사·해결 상태
- 인벤토리와 선택 아이템
- 발견 단서
- 해결 퍼즐
- 진행 중 연출과 입력 잠금
- 현재 목표
- 힌트 사용 단계
- 최종 추리 상태

### 22.2 상태 변경 원칙

- 화면 그림을 먼저 바꾸고 상태를 나중에 기록하지 않는다.
- 게임 상태 변경과 연출 시작 시점을 분리한다.
- 연출 완료 전 다음 퍼즐을 활성화하지 않는다.
- 같은 이벤트가 두 번 실행되지 않게 완료 상태를 확인한다.
- 장면 이동 후에도 해결 상태가 유지되어야 한다.

### 22.3 저장 범위

현재 MVP에서는 기기 내부 저장을 사용한다.

저장 대상:

- 에피소드 시작 여부
- 마지막 안정 장면
- 획득 아이템과 사용 상태
- 핵심 단서
- 해결 퍼즐
- 에피소드 완료
- 경험치와 꽃숲 성장

애니메이션 중간 프레임은 저장하지 않는다. 연출 직전 또는 완료 후의 안정 상태를 저장한다.

### 22.4 중단 복귀

앱을 중단했다가 돌아왔을 때 다음을 보장한다.

- 이미 얻은 아이템이 사라지지 않음
- 해결한 퍼즐이 초기화되지 않음
- 사용한 아이템이 중복 생성되지 않음
- 잠금 상태가 영구적으로 남지 않음
- 현재 목표가 실제 진행 상태와 일치함

## 23. 유지보수 가능한 설계 구조

본편은 기술 검증 파일 하나를 계속 확장하지 않는다. 다음 역할을 분리한다.

```text
Episode Screen
├── Episode Game
├── Episode State
├── Scene Definitions
├── Scene Components
├── Interaction Rules
├── Puzzle Controllers
├── Inventory Overlay
├── Hint Overlay
├── Clue Notebook Overlay
└── Audio Controller
```

### 23.1 에피소드 화면

- Flutter 화면과 Flame `GameWidget`을 연결한다.
- Overlay 등록과 화면 생명주기를 관리한다.
- 구체적인 퍼즐 규칙을 직접 포함하지 않는다.

### 23.2 에피소드 상태

- 진행 상태의 단일 기준이다.
- 장면과 Overlay가 같은 상태를 공유한다.
- 상태 변경은 명확한 메서드를 통해서만 수행한다.

### 23.3 장면 정의

각 장면은 최소 다음 정보를 가진다.

```text
sceneId
name
background
initialState
navigationTargets
interactiveObjects
visualStates
entryEvents
```

### 23.4 오브젝트 정의

```text
objectId
sceneId
role
hitArea
visibleWhen
enabledWhen
interactionType
reactionBefore
reactionAfter
resultEvent
```

### 23.5 퍼즐 정의

```text
puzzleId
sceneId
storyPurpose
requiredClues
requiredItems
inputRule
successRule
failureFeedback
successEvents
hints
```

### 23.6 이벤트

장면과 퍼즐의 의존관계는 직접 서로를 수정하기보다 이벤트로 연결한다.

예:

```text
key_acquired
→ inventory updated

fountain_lock_opened
→ fountain scene changed
→ hidden passage enabled
→ current goal updated
```

이 방식으로 한 퍼즐 수정이 다른 장면 코드를 불필요하게 변경하지 않게 한다.

## 24. 에피소드 콘텐츠 예산

한 에피소드의 기본 제작 범위는 다음과 같다.

| 요소 | 기준 |
|---|---:|
| 주요 장면 | 4~6개 |
| 확대 조사 | 3~5개 |
| 핵심 퍼즐 | 4~6개 |
| 최종 추리 | 1개 |
| 총 아이템 | 4~7개 |
| 핵심 증거 | 3개 |
| 장면 간 연결 | 2회 이상 |
| 주요 장면 상태 변화 | 장면당 2회 이상 |
| 큰 연쇄 연출 | 1~2회 |
| 이야기상 의미가 있는 보조 반응 | 8~15개 |
| 단계별 힌트 | 핵심 퍼즐당 3단계 |
| 목표 플레이 시간 | 8~12분 |

범위를 초과하면 먼저 장면이나 퍼즐을 줄인다. 기술 구조를 복잡하게 만들어 모두 포함하지 않는다.

## 26. 접근성과 아동 안전 기준

- 주요 텍스트는 쉬운 문장으로 작성한다.
- 어려운 용어는 장면 속 표현으로 바꾼다.
- 공포, 잔혹, 갑작스러운 큰 소리와 점프 스케어를 사용하지 않는다.
- 시간 제한은 기본적으로 사용하지 않는다.
- 색만으로 단서와 상태를 구분하지 않는다.
- 작은 화면에서도 버튼과 터치 영역을 유지한다.
- 오답 대사는 비난, 조롱 또는 실망을 표현하지 않는다.
- 힌트와 뒤로 가기는 항상 찾기 쉬운 위치에 둔다.
- 대사와 애니메이션은 건너뛸 수 있되 핵심 단서는 수첩에 남긴다.

## 29. 품질 검증 기준

### 29.1 설계 검증

- 사건의 목적을 시작 30초 안에 이해할 수 있는가
- 모든 퍼즐의 단서를 게임 안에서 찾을 수 있는가
- 장면 간 연결이 최소 2회 있는가
- 수학이 실제 장치 또는 사건에 필요하게 사용되는가
- 무작위 탭 없이 진행할 수 있는가
- 막혔을 때 힌트가 다음 행동을 안내하는가
- 해결 결과가 장면 변화로 보이는가
- 결말이 핵심 증거를 모두 설명하는가

### 29.2 기능 검증

- 장면 이동 후 상태가 유지되는가
- 확대 조사 후 정확한 장면으로 복귀하는가
- 아이템 선택, 해제, 사용과 소모가 정확한가
- 잘못된 아이템이 사라지지 않는가
- 드래그 실패 시 원위치로 복귀하는가
- 성공 시 스냅과 완료 상태가 유지되는가
- 연출 중 입력이 차단되고 완료 후 해제되는가
- Overlay가 열린 동안 배경 입력이 차단되는가
- 저장 후 복귀해도 진행이 일치하는가

### 29.3 자동 검증

## 30. 사용자 테스트 기준

초등학교 5학년 대상 테스트에서는 정답률보다 다음 행동을 관찰한다.

1. 시작 후 별도의 설명 없이 첫 행동을 시도하는가
2. 장면 변화와 현재 목표를 따라가는가
3. 무작정 전부 누르지 않고 수상한 물건을 관찰하는가
4. 아이템 형태를 보고 사용처를 추측하는가
5. 이전 장면의 단서를 기억하거나 수첩을 확인하는가
6. 수학을 시험이 아니라 사건 해결 도구로 받아들이는가
7. 오답 후 불안해하지 않고 다시 시도하는가
8. 정답 연출에서 성취감을 표현하는가
9. 결말에서 캐릭터의 사정을 이해하는가
10. 다음 에피소드를 해보고 싶다고 느끼는가

핵심 성공 기준은 다음 세 가지다.

- 중간에 그만두지 않고 사건 해결까지 진행함
- 수학 활동 때문에 게임 흐름이 끊겼다고 느끼지 않음
- 다음 방문 의향을 보임

## 32. 최종 결정

Rumi의 방탈출 제작 기준을 다음과 같이 확정한다.

1. Flutter와 Flame을 유지한다.
2. 고정 2D 장면과 확대 조사 구조를 사용한다.
3. 인벤토리, 힌트, 단서 수첩과 대화는 Flutter Overlay로 구현한다.
4. 장면, 오브젝트, 드래그, 애니메이션과 시각 효과는 Flame으로 구현한다.
5. 한 에피소드는 주요 장면 4~6개, 약 10분 분량으로 설계한다.
6. 모든 주요 장면은 진행에 따라 눈에 띄게 변한다.
7. 아이템은 형태와 상황으로 사용처를 추론할 수 있게 한다.
8. 퍼즐은 이야기 속 장치이며 해결 결과가 세계 변화로 이어진다.
9. 수학은 분류, 배치, 반복, 개수와 추론 규칙으로 사용한다.
10. 오답과 힌트에는 페널티를 두지 않는다.
11. 최종 단계는 핵심 증거를 연결하는 사건 추리로 구성한다.
12. Episode 1 상세 설계가 승인된 후 본편을 구현한다.

> Rumi의 목표는 아이가 정답 버튼을 찾는 것이 아니라, 정원을 살펴보고 물건을 만지며 변화를 만들고, 서로 떨어진 단서를 연결해 사건의 진실을 스스로 밝혀내게 하는 것이다.

# Rumi Flame 방탈출 구현 가능성 검증 보고서

- 문서 상태: 확정본
- 작성일: 2026-07-27
- 적용 프로젝트: 루미아의 별정원(Rumi)
- 적용 범위: 2D 장면형 방탈출 공통 기능 및 Episode 1 재설계
- 선행 문서: `docs/ESCAPE_GAME_ANALYSIS.md`

---

## 1. 검증 목적

대표 방탈출 게임 분석에서 채택한 재미 요소가 현재 기술 스택인 Flutter와 Flame에서 실제로 구현 가능한지 확인했다.

이번 검증은 단순히 화면을 그릴 수 있는지를 확인하는 작업이 아니다. 다음 조건을 만족하는지 확인하는 것이 목적이다.

1. 장면형 방탈출의 핵심 조작을 Flame으로 구현할 수 있는가
2. Flutter UI와 Flame 게임 화면을 안정적으로 함께 사용할 수 있는가
3. 작은 모바일 화면에서도 터치와 드래그가 가능한가
4. 기존 Rumi 모험 화면과 기능을 손상하지 않고 별도 프로토타입을 추가할 수 있는가
5. 자동 검사와 Web 빌드를 통과하는 유지보수 가능한 구조인가

---

## 3. 생성된 검증 화면

검증 화면은 다음 파일에 독립적으로 구현했다.

```text
lib/features/adventure/flame/escape_feasibility_screen.dart
```

기존 Episode 1 프로토타입은 삭제하거나 교체하지 않았다. 기존 모험 화면 우측 상단의 `방탈출 기술 검증` 버튼으로 새 검증 화면에 진입할 수 있다.

### 검증 화면 구성

```text
정원 장면
├── 켜고 끌 수 있는 등불
├── 아이템을 사용할 수 있는 별 자물쇠
├── 확대 조사 장면 이동
└── 드래그 퍼즐 장면 이동

확대 조사 장면
└── 별열쇠 획득

드래그 퍼즐 장면
└── 별조각 이동 및 스냅 판정

Flutter 오버레이
├── 인벤토리
├── 단계별 힌트 예시
└── 검증 현황
```

## 4. 기능별 검증 결과

## 4.1 장면 이동과 상태 유지

### 구현 내용

- 정원, 확대 조사, 드래그 퍼즐의 세 장면을 전환한다.
- 장면을 이동해도 등불 상태, 획득 아이템, 해결된 퍼즐과 열린 문 상태를 유지한다.
- 확대 화면에서 돌아오면 원래 정원 장면으로 복귀한다.

### 결과

**통과 — 채택 등급 A**

Episode 1은 고정된 주요 장면 4~6개와 확대 장면 3~5개를 안정적으로 구성할 수 있다.

---

## 4.2 확대 조사와 이전 장면 복귀

### 구현 내용

- 정원에서 작업대를 누르면 확대 조사 장면으로 이동한다.
- 확대 장면에서 별열쇠를 발견하고 획득한다.
- 뒤로 이동하면 정원 장면의 기존 상태가 그대로 유지된다.

### 결과

**통과 — 채택 등급 A**

`전체 장면 → 조사 대상 확대 → 원래 장면 복귀` 구조를 Episode 1의 기본 장면 계층으로 사용한다.

---

## 4.3 인벤토리 획득·선택·사용

### 구현 내용

- 시작 아이템인 꽃잎과 획득 아이템인 별열쇠를 Flutter 인벤토리에 표시한다.
- 아이템을 눌러 선택하거나 선택을 해제할 수 있다.
- 선택한 별열쇠를 Flame 장면의 자물쇠에 사용할 수 있다.
- 사용 결과는 게임 상태와 장면 렌더링에 즉시 반영된다.

### 결과

**통과 — 채택 등급 A**

인벤토리는 Flame 내부에 직접 그리지 않고 Flutter Overlay로 구현한다. 이 방식은 텍스트, 아이콘, 접근성, 반응형 배치와 테스트 측면에서 더 안정적이다.

---

## 4.4 잘못된 아이템 사용 반응

### 구현 내용

- 꽃잎을 별 자물쇠에 사용하면 진행을 막거나 벌점을 주지 않는다.
- `꽃잎은 별 모양 열쇠구멍과 맞지 않아요`라는 구체적인 반응을 제공한다.
- 아이템은 소모되지 않으며 즉시 다른 행동을 시도할 수 있다.

### 결과

**통과 — 채택 등급 A**

오답은 실패 화면이 아니라 세계의 규칙을 이해하게 하는 짧은 피드백으로 처리할 수 있다.

---

## 4.5 드래그와 스냅 판정

### 구현 내용

- 별조각을 손가락이나 포인터로 이동한다.
- 목표 홈과 일정 거리 이내에서 놓으면 홈 중심으로 자동 정렬한다.
- 목표에서 멀리 놓으면 원래 위치로 돌아간다.
- 해결 상태는 장면을 나갔다 돌아와도 유지된다.

### 결과

**통과 — 채택 등급 A**

드래그 조각 수를 제한하고 충분한 터치 범위를 제공하면 분류, 묶기, 조각 맞추기 퍼즐을 구현할 수 있다.

### 적용 제한

- 한 화면의 동시 드래그 조각은 가능한 6개 이하로 제한한다.
- 작은 물체를 정밀하게 맞추는 조작은 사용하지 않는다.
- 손가락에 가린 상태에서도 목표 위치를 알 수 있게 테두리나 빛을 표시한다.

---

## 4.6 장치 연쇄 애니메이션과 입력 잠금

### 구현 내용

- 별열쇠를 사용하면 약 1.6초 동안 문 장치가 단계적으로 열린다.
- 애니메이션 진행 중에는 중복 터치와 장면 이동을 차단한다.
- 완료 후 입력 잠금을 해제하고 열린 문 상태를 유지한다.
- 완료 시 짧은 효과음을 요청한다.

### 결과

**통과 — 채택 등급 A**

서랍, 덮개, 비밀문, 별빛 장치처럼 여러 요소가 순차적으로 움직이는 정답 연출을 구현할 수 있다.

### 구현 원칙

- 애니메이션 중 입력 잠금 상태를 명시적으로 관리한다.
- 화면 연출과 실제 게임 상태 변경 시점을 분리한다.
- 애니메이션이 끝나기 전에 다음 퍼즐이 활성화되지 않게 한다.

## 4.8 작은 화면과 터치 영역

### 구현 내용

- 기존 360×640 화면 대응 테스트와 함께 전체 테스트를 실행했다.
- 검증 화면은 화면 크기를 기준으로 장면 영역과 오브젝트 위치를 계산한다.
- 주요 오브젝트는 보이는 이미지보다 넓은 터치 영역을 사용한다.
- 새 검증 버튼이 기존 모험 오브젝트를 가리지 않도록 우측 상단으로 분리했다.

### 결과

**자동 검사 통과 — 실제 태블릿 확인 필요**

자동 테스트에서는 기존 작은 화면 흐름과 새 기능이 함께 통과했다. 다만 손가락 조작감, 버튼 크기와 기기별 SafeArea는 Galaxy 태블릿에서 직접 확인해야 한다.

## 4.9 효과음과 앱 생명주기

### 구현 내용

- 별조각 스냅과 문 개방 완료 시 짧은 WAV 효과음을 재생하도록 구현했다.
- 효과음은 별도 파일 없이 검증할 수 있도록 메모리에서 임시 WAV 데이터를 생성한다.
- 앱이 백그라운드로 이동하면 Flame 엔진과 오디오를 일시정지한다.
- 앱 복귀 시 엔진을 재개한다.
- 화면 종료 시 오디오 플레이어와 상태 객체를 해제한다.

### 결과

**컴파일·Web 빌드 통과 — 실제 기기 재생 확인 필요**

오디오 호출과 생명주기 구조는 빌드 가능한 상태로 검증했다. Android 실제 기기에서 무음 모드, 볼륨, 백그라운드 전환과 재진입을 추가 확인한다.

## 6. 구현 중 확인된 문제와 조치

## 6.1 컴포넌트 속성 이름 충돌

### 원인

검증 화면의 `key` 영역 이름이 Flame 컴포넌트가 이미 사용하는 `key` 속성과 충돌했다.

### 조치

`keyRect`로 역할이 명확한 이름을 사용했다.

### 예방 원칙

Flame과 Flutter가 사용하는 공통 이름인 `key`, `position`, `size`, `children`은 커스텀 의미로 재정의하지 않는다.

---

## 6.2 드래그 이벤트의 상위 호출 누락

### 원인

`onDragStart`와 `onDragEnd`에서 상위 이벤트 처리 호출이 누락되어 정적 분석 오류가 발생했다.

### 조치

각 이벤트에서 `super`를 먼저 호출하도록 수정했다.

### 예방 원칙

Flame 생명주기와 입력 콜백을 재정의할 때 정적 분석 결과를 기준으로 상위 호출 필요 여부를 확인한다.

---

## 6.3 새 진입 버튼이 기존 테스트를 방해함

### 원인

검증 버튼을 기존 하단 체험 버튼 위에 추가하면서, 작은 화면 테스트에서 장면 오브젝트의 터치 위치를 가로막았다.

### 조치

기존 `Flame 1단계 전체 체험` 버튼은 그대로 유지하고, 새 `방탈출 기술 검증` 버튼을 우측 상단으로 이동했다.

### 예방 원칙

기존 화면 위에 임시 개발 진입점을 추가할 때 다음을 확인한다.

- 기존 터치 영역을 가리지 않는가
- 작은 화면에서도 겹치지 않는가
- 기존 테스트를 모두 다시 실행했는가

## 7. 최종 기술 판단

### 결론

> **Rumi의 2D 장면형 방탈출 게임은 현재 Flutter·Flame 기술 스택으로 구현 가능하다. Flame을 유지한다.**

대표 게임 분석에서 채택한 핵심 재미 요소는 다음과 같으며 모두 구현 가능한 범위다.

- 고정된 여러 장면 사이의 이동
- 장면 상태 유지와 변화
- 오브젝트 확대 조사
- 아이템 획득·선택·사용
- 다른 장면의 단서 연결
- 드래그·스냅·탭 순서·제한 회전 퍼즐
- 장치의 연쇄 애니메이션
- 입력 잠금과 상태 전환
- 힌트·인벤토리·대화 Overlay
- 효과음과 배경음

따라서 엔진 제약 때문에 재미를 낮춘 대체 방안을 사용할 필요가 없다.

## 9. 제외 기능

다음 기능은 구현 가능 여부와 관계없이 현재 Rumi 범위에서 제외한다.

- 완전한 3D 공간 회전
- 자유로운 3D 물체 조사
- 정밀 물리 시뮬레이션
- 반사신경 중심 액션 퍼즐
- 많은 물체가 동시에 움직이는 대형 장치
- 외부 메모가 필요한 복잡한 암호
- 작은 물체를 픽셀 단위로 찾는 퍼즐

이 기능들은 10분 세션, 초등학교 5학년 대상, 개발 유지보수성과 맞지 않는다.

## 10. 프로토타입의 한계

현재 검증 화면은 구현 가능성 확인용이며 Episode 1 본편이 아니다.

- 배경과 오브젝트는 코드로 그린 임시 도형이다.
- 장면 데이터가 검증 화면 한 파일에 있다.
- 실제 Episode 1의 이야기와 퍼즐 의존관계는 적용하지 않았다.
- 정식 효과음과 배경음이 아니다.
- 진행 상태를 기기에 저장하지 않는다.
- 실제 Galaxy 태블릿 조작 테스트는 남아 있다.

본편 구현 시 검증 코드를 그대로 확장하지 않고, 승인된 Episode 1 상세 설계에 맞춰 장면·상태·퍼즐·Overlay 역할을 분리한다.

## 11. 실제 기기 확인 절차

앱에서 다음 순서로 확인한다.

1. 오늘의 모험 화면으로 이동한다.
2. 우측 상단의 `방탈출 기술 검증`을 누른다.
3. 등불을 켠다.
4. `확대 조사`로 이동해 별열쇠를 획득한다.
5. 정원으로 돌아와 등불이 켜진 상태인지 확인한다.
6. 꽃잎을 선택하고 문을 눌러 잘못된 아이템 반응을 확인한다.
7. 별열쇠를 선택하고 문을 눌러 연쇄 개방 연출을 확인한다.
8. `조각실`에서 별조각을 홈 밖에 놓아 원위치 복귀를 확인한다.
9. 다시 끌어 홈에 놓고 스냅을 확인한다.
10. 힌트와 검증 현황을 열어 배경 입력이 차단되는지 확인한다.
11. 효과음이 들리는지 확인한다.
12. 앱을 백그라운드로 보냈다가 돌아와 정상 동작하는지 확인한다.

### 실제 기기 합격 기준

- 버튼과 오브젝트를 한 번에 누를 수 있음
- 드래그 중 조각이 손가락에 완전히 가려지지 않음
- 장면 이동 중 상태가 초기화되지 않음
- 애니메이션 중 중복 입력이 발생하지 않음
- 오버레이를 닫은 뒤 입력이 정상 복구됨
- 효과음 재생과 앱 복귀에 오류가 없음
